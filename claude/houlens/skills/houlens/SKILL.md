# 法レンズで判例と条文を調べて答える

法レンズのMCPサーバは、日本の判例と条文を検索し、判決文の原文と出典を返す。法的な評価と事案への当てはめは返さない。評価はClaudeの側で行い、最終の判断は弁護士が行う。

判例の内容は、記憶でなく必ず法レンズのツールで取得する。判決文の本文は `read_case_text` で読む。

## 判例検索まで進むかを決める

- 具体的な事実関係への見通し、書面や依頼者への回答の根拠づけ、判例の明示の要求のときは、先に `search_cases` で関連する判例を探す。重要な判例は `get_case` と `read_case_text` で内容を確かめてから答える
- 一般的な法理の確認や概念の整理のような壁打ちの段階では、先に自分の法的な知識で論理的に答える。そのうえで、関連する判例を法レンズで検索できることを末尾に短く添え、利用者が求めたら検索する
- どちらの段階か迷うときは、先に論理で答えて検索を提案する

## 判例を特定してから言及する

壁打ちの段階でも、次の決まりは必ず守る。

- 回答で判例に言及する前に、その判例を特定する。`search_cases` で特定できた判例は判例IDが付くので照合済みである
- 利用者が挙げた判例名と、記憶から出した判例は、言及の前に事件番号を `lookup_case_citation` で照合する。事件番号が無ければ裁判所名と言渡日の組を渡す。判例名しか分からなければ `search_cases` でその判例を特定する
- 確認と言えるのは、事件番号まで一致した照合か、`search_cases` での特定だけである。確度区分が reference の一致が並んだだけでは確認にならない
- 1件も当たらなかった判例、`citation_verified` が false の一致、書誌の食い違いの warning が付いた一致は、確認済みとして言及しない。触れるときは、書誌を確認できていない旨の留保を添える
- `verification` が mismatch の項目は、引用の取り違えの可能性として利用者に伝える
- 照合で1件も当たらなかった判例は「法レンズ収録外」と明示し、実在と内容は原典で確かめる必要があると伝える。reference の一致しか得られなかった判例は収録外と呼ばず、特定に至っていないと伝える
- 記憶にある判例名を、照合なしに書かない

## 出典を明示する

- 判例に言及するときは、応答に含まれる裁判所・言渡日・事件番号と判例ID (case_id) を必ず添える
- 判断の核心は要約に丸めず、判決文の実文を短く引用する。どの判例のどの部分かを添え、必要な箇所に絞る
- 判例を最初に示すときに、判例IDを伝えてもらえばいつでも続きや別の部分を読めると一言案内する
- 判例に言及した回答の末尾に、法レンズで確認した判例の出典の一覧を、裁判所・言渡日・事件番号と判例IDの形でまとめる。収録外や特定に至っていない判例は、一覧の中で分けて載せる。判例が1件だけの短い回答では一覧を省いてよい
- 引用した判決文の中に現れる別の判例は、その判決自身の引用であり、照合を経ていない。議論の根拠に使うときは照合してから使う
- 文献や学説のような判例以外の根拠は、判例と混ざらないように出所を添える

## 判決文のテキストと原本PDFの距離

- 判決文のテキストは、原本PDFから機械的に抽出したもので、原本そのものではない。改行の位置と、対応表を持たない書体の字が制御文字になる点で、体裁は原本と同じではない
- 書面に引用する場合は、原本の確認が必須である。書面への引用の話になったら、`get_case` の `original.url` と `original.how_to_view` の案内を利用者へ示す。リンクが無い環境では、法レンズの原本ページ (/original/判例ID) を開いてログインする操作を案内する
- `original.url` は、利用者本人がブラウザで原本PDFを確認するためのリンクである。Claude自身はこのURLを開かない。開けないことを理由に、本文を確認できないと判断したり、判例が収録されていないと読み替えたりしない
- 引用する文言の字が原本と一致するかを確かめるときは、`read_original_page` に `pdf_page` か `passage_id` を渡す。原本のページの画像と抽出したテキストを突き合わせ、食い違いがあれば原本の字を優先して利用者に伝える。最終の確認は利用者本人が原本ページで行う
- 本文には、原本PDFの余白の行番号 (5、10、15 …) と下端の頁番号が、数字だけの行として文の途中に入る。本文そのものの数字もあるので、前後の文と原本の頁で見分けてから引用する

## 判決文を読む

- 全文を一度に読み込まず、`read_case_text` で必要な範囲だけ読む
- 裁判所の判断から読むときは、`get_case` の `sections` で `section_type` が judgment の区画の `section_seq` を確かめ、その値を `read_case_text` に渡す
- judgment の区画は、判断にあたる見出しの語彙で機械的に取った範囲で、当事者の主張の文と引用が混ざる。引用する前に、その文の主語が裁判所なのか、原告や被告や控訴人なのかを確かめる。`basis` が fallback の区画は受け皿なので、特に主語を確かめる
- 探している記述がその区画に無いときは、ほかの区画か `chunk_index` で判決文の全体へ広げる
- 特定の文言の位置は `find_in_case` で探し、一致の `passage_id` を `read_case_text` に渡して前後を読む。`section_type` を渡すと、その区画の中の一致だけに絞れる
- 最高裁判所の判決を引くときは前後を広めに読み、その文が最高裁判所自身の判断か、退けた原審の判断の要約や上告理由かを確かめる

## 検索結果の読み方

- 検索が0件でも、判例が存在しないことの証明にはならない。「該当判例は存在しない」と断定せず、収録範囲の限界を利用者に伝える
- 0件の応答には収録範囲 (coverage) が載るので、それを添えて限界を報告する。0件の報告のために `get_coverage` を別に呼ばなくてよい。結果は返ったが期待する判例が無いときと、収録範囲そのものを問われたときは `get_coverage` を使う
- 0件の応答の `next_actions` は、そのまま渡せる引数つきの次の呼び出しの案である
- `alerts` の code と note は、その応答にだけ成り立つ事情を書いている。結果を読む前に目を通す
- `mode` が keyword の応答の `count_scope` にある `keyword_matches` は、収録全体でその語に当たった判例の件数である。返した件数と同じなら全件の excerpt を読み、多いときは `limit` を上げる
- `score` は意味の近さで、法的な論点の一致ではない。抜粋を読んで関連を確かめる

## 書き下した query で検索し直す

- `alerts` に all_reference が付いたときは、相談文のままより、争点と裁判所の判断の枠組みを判決文の言い回しで書き下した `query` の方が見つけやすい
- 上位の excerpt にある規範の文を材料に `query` を書き下し、利用者に確かめてから `search_cases` を引き直す
- 法レンズのサーバは `query` を書き下さない。書き下すのはClaudeの側である

## 条文を引く

- 条文は `get_statute` で引く。判例と併せて議論するときは、判例の言渡日を `reference_date` に渡して、言渡日時点のリビジョンを確かめる
- 言渡日のリビジョンは、改正の前後を比べるための材料である。その事件に適用される法とは限らない。行為時の条文が必要なときは、その日付を `reference_date` に渡して引き直す
- 古い言渡日でリビジョンを取得できないときは、その旨とその法令で引ける最古の基準日が返る。当時の条文を原典で確かめる必要があることを利用者に伝える
- 改正が論点に関わるときは、`compare_statute_revisions` で改正前後の条文と行の差分を1回で引く
- 略称や通称や旧題名しか分からないときは、先に `resolve_law_name` で候補を引き、候補の `law_id` を `get_statute` に渡す。候補が複数あるときは文脈で選び、自動で1つに決めない
- 経過措置は附則にある。本則の条の応答に付く `suppl_mentions` で附則の条を確かめ、附則の本文を引く
- 条の番号が分からないときは `list_statute_articles` で条見出しの一覧を引く
- 法令名も条番号も分からない相談文では、`search_statutes` で条の候補を意味の近さで引く。当たった条は結果の `get_statute_args` をそのまま `get_statute` に渡して引き直す。`article_key` を `article` にそのまま渡さない
- 関係しそうな条と裁判例を一度に見たいときは `search_cases_and_statutes` を使う。判例の `score` と条文の `score` は別の値なので、大小を比べない

## 呼び出しの上限とエラー

- 呼び出しの回数には1分と1日の上限がある。断られたら同じ呼び出しをすぐに繰り返さず、応答にある秒数だけ待ってから続ける
- タイムアウトや一時的な失敗のエラーが続くときは、https://status.houlens.jp で稼働の状態とメンテナンスの予定を確かめられると利用者に伝える
